# php-practice

PHPの基礎を学ぶための練習用ファイル集。

## comment.php のバグ修正について

`comment.php`（コメント投稿フォーム）に潜んでいた3つのバグを発見し、修正しました。

### 見つけた問題点

1. **比較演算子の間違い（代入バグ）**
   `if ($name = "")` のように、比較演算子 `===` の代わりに代入演算子 `=` が使われていた。これにより `$name` が常に空文字で上書きされ、さらに条件式が常に false と評価されるため、名前が空でもエラーにならず投稿が成立してしまっていた。

2. **XSS脆弱性（エスケープ漏れ）**
   ユーザーが入力した `$name` と `$comment` を、エスケープせずそのままHTMLに出力していた。名前欄などに `<script>...</script>` のようなコードを入力されると、そのままページに埋め込まれて実行されてしまう危険があった。

3. **コメント欄の未入力チェック漏れ**
   バリデーションが名前の空欄しかチェックしておらず、コメント欄を空のまま投稿しても、そのまま投稿が成立してしまっていた。

### 修正した内容

1. `if ($name = "")` を `if ($name === "")` に修正し、意図通り「名前が空文字かどうか」を判定するようにした。
2. 出力箇所を `htmlspecialchars($name)` ／ `htmlspecialchars($comment)` に変更し、`<` や `>` などの記号がタグとして解釈されずエスケープして表示されるようにした。
3. 判定条件を `if ($name === "" || $comment === "")` に変更し、名前・コメントのどちらかが空でもエラーメッセージを表示するようにした。

修正後、`php -l` での構文チェックと、ローカルサーバー（`php -S`）を使った実地テスト（両方空／コメントのみ空／正常投稿／`<script>`タグを含む入力）を行い、いずれも意図通りの挙動になることを確認済み。

### 学んだこと

- `=`（代入）と `==`／`===`（比較）は見た目が似ていて間違えやすく、`if` 文の条件式に代入を書いてしまうと、エラーにならずに静かに意図と違う動作をしてしまう。特に「常に false（またはtrue）になる」バグは気づきにくいので注意が必要。
- ユーザーからの入力（`$_POST` の値）は、画面に出力する前に必ず `htmlspecialchars()` でエスケープしないと、XSS（スクリプト埋め込み）の被害につながる。
- バリデーションは「どれか1つの項目だけ」ではなく、フォームの入力項目すべてに対して漏れなく行う必要がある。項目が増えるほど「チェックし忘れ」が起きやすい。
- バグ修正のあとは、修正した箇所だけでなく「境界のパターン（両方空・片方だけ空・正常系）」を一通り実際に動かして確認することで、直したつもりで直っていない見落としを防げる。
